# 青禾计划 · 开发路线图

> 本文件是项目台账的执行计划。每个阶段开始前需经你确认，完成后把结果同步回 `docs/project-ledger.md`。

## 使用方式

- 每个阶段都写清楚“为什么做、做什么、验收标准”。
- 你只需要确认顺序，或修改某一阶段的范围。
- 未确认的阶段不开始写代码。
- 每完成一个阶段先本地提交；经你确认后再推送 GitHub 并打 Git 标签。

## P0：可玩原型基线

- 目标：跑通“建院、招生、审批、年度结算、榜单、官网”的首年循环。
- 已完成内容：合同开局、学院与专业、招生投放、年度财务、赛事、社团、校企、校友、校园地图、榜单、官网新闻。
- 状态：已发布到 GitHub Pages 与 CDN。
- 验收结果：首年招生与年度报告流程已通过浏览器测试。

## P1：新手体验与数值平衡

- 目标：让新玩家不迷路，经济循环可持续，前三年不轻易破产。
- 范围：
  - 新手教程改为可跳过的任务卡片。
  - 审批、招生、年度结算增加更直观的反馈。
  - 调整民办专科前三年的收入与成本曲线。
  - 增加“办学目标”面板，让玩家知道下一步该做什么。
- 验收标准：
  - 一名没有看说明的玩家能独立完成首年招生。
  - 合理经营下，前三年资金不会无故归零。
  - 所有按钮和关键数据有文字解释。

## P2：校园生活与人物故事

- 目标：让学校有“人”，让每一年有值得记住的事。
- 范围：
  - 学生个体档案：入学分数、专业、去向。
  - 教师个体档案：招聘、职称、离职。
  - 年度事件：舆情、检查、合作、竞赛结果。
  - 社团与赛事的长期成长。
- 验收标准：
  - 玩家能看到一批具体的学生与教师。
  - 年度事件会影响后续若干年，而不是一次性奖励。
  - 校园生活页面有可重复访问的价值。

## P3：学科生长与科研深化

- 目标：让学科选择真正影响学校长期定位。
- 范围：
  - 专业目录与学科评估的更深耦合。
  - 国家级、省级科研项目的周期管理。
  - 硕士点、博士点的评估过程。
  - 教师科研团队与平台建设。
- 验收标准：
  - 不同学科方向带来不同资源和排名变化。
  - 科研投入与产出可追溯，不再只是加数值。

## P4：招生地图与排名可视化

- 目标：让招生和排名更有空间感和对比感。
- 范围：
  - 四川省招生生源地图。
  - 竞争对手的动态表现。
  - 排名变化曲线与分项得分。
- 验收标准：
  - 玩家能看到自己学校在四川的招生范围变化。
  - 排名上升或下降能对应到具体办学指标。

## P5：手机体验与正式美术

- 目标：手机操作更顺手，视觉更有辨识度。
- 范围：
  - 针对小屏优化所有表单与长页面。
  - 校园地图、合同、官网的美术细化。
  - 图标、加载状态和空状态统一。
- 验收标准：
  - 主流手机宽度下无横向溢出、无错位按钮。
  - 关键操作在 3 次点击内完成。

## P6：云端存档与账号

- 目标：跨设备继续游戏。
- 前置条件：需要后端服务或第三方账号系统。
- 范围：待你确认后再单独立项，当前不纳入近期开发。

## 推荐执行顺序

按风险与体验价值，建议顺序为：

P1 → P2 → P4 → P3 → P5。

P3 与 P4 可交换，其余建议保持。

## 变更管理

- 你确认的内容进入 `docs/project-ledger.md` 的“已确认决策”。
- 每次变更先改文档，再改代码。
- 未写入文档的想法不作为开发依据。
- 每个已确认版本打 Git 标签，例如 `v0.1.0`、`v0.2.0`。
